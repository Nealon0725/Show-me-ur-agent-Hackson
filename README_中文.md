# Clearhire：简历筛选界面

这是为 Resume Screening 黑客松题目完成的响应式前端。可以直接打开 `dist/index.html` 使用，也可以部署 `dist` 目录；推荐使用发布后的网址或 HTTP 预览，浏览器对本地 PDF 的预览支持可能不同。

## 已实现的界面与交互

- 简历筛选：三个岗位切换、姓名/职位/技能搜索、状态筛选、来源筛选、排序与分页。
- 候选人详情：四项岗位证据、原文引用、个人资料、评审备注。
- 简历预览：PDF 与作者文本版本切换，支持下载原始文件。
- 候选人对比：勾选同一岗位的 2–3 位候选人，并排查看工作证据。
- 入围名单：人工加入或移出候选人，导出 CSV。
- 文件导入与分析：点击选择或拖放 PDF/DOCX，每份最多 5 MB、一次最多 50 份；本地 Python 后端读取文字并返回逐项证据。
- 演示流程：明确标注使用预设结果的进度演示。
- 中英文界面切换，桌面、平板和手机布局，键盘焦点、弹窗关闭与减少动态效果支持。

样本数据包含之前准备的 60 位虚拟候选人，三个岗位各 20 人。PDF、姓名、经历和参考证据均为虚构。

## 必须准确表述的边界

60 位样本候选人的证据状态来自预先编写的参考结果。新上传的 PDF/DOCX 会由本地 Python 后端真实读取并分析；默认离线规则仅覆盖三个演示岗位，配置学校 Gateway 或 OpenAI 后可使用模型证据提取。扫描图片型 PDF 尚未接入 OCR。

新导入的文件只发送到本机 `127.0.0.1` 上运行的 Python 服务，不会上传到公共展示网站。文件引用、入围选择、语言和备注仍只保存在当前浏览器，刷新后上传候选人会消失；正式使用仍需登录、权限和共享评审记录。

中文模式翻译界面文字和岗位条目标题；英文简历原文、证据引文和完整岗位描述保留英文，方便现场展示及核对。

## 本地打开和修改

1. 创建 `.venv` 并安装 `requirements.txt`。
2. 运行 `RECRUITMENT_AGENT_PROVIDER=rules .venv/bin/python -m backend.server`。
3. 浏览器打开 `http://127.0.0.1:8000`。
4. 修改界面逻辑后运行 `node build.mjs`，重新生成 `bundle.js`。

项目无运行时第三方 JavaScript 依赖。字体使用 Manrope 和 DM Sans，网络不可用时回退到系统字体。图标使用内嵌 SVG；界面不加载真实候选人的头像。

可选 HTTP 预览示例：`python3 -m http.server 8765 --directory dist`，然后打开 `http://localhost:8765`。

## 目录

| 路径 | 用途 |
|---|---|
| `index.html` | Clearhire 页面入口，由 Python 后端提供 |
| `main.js` | 页面结构、交互及后端 API 调用 |
| `data.js` | 三个岗位与 60 位虚拟候选人 |
| `styles.css` / `accessibility.css` | 视觉、响应式布局和可访问性 |
| `bundle.js` | 打包后的浏览器脚本，不直接编辑 |
| `build.mjs` | 无依赖的脚本打包工具 |
| `backend/server.py` | 静态界面、文件读取和分析 API |
| `agents/ui_adapter.py` | 后端证据状态到 Clearhire UI 的转换 |
| `设计与接入说明.md` | 视觉规则、交互与后端接入要点 |

## 三分钟演示顺序

1. 在「简历筛选」中选择软件开发岗位，说明 20 位候选人及四项条件。
2. 点击「运行演示」，明确这是 UI 演示，并展示流程状态。
3. 搜索一个技能，打开候选人，点击「查看原文」。
4. 切到「需澄清」，说明缺信息不等于能力不足。
5. 勾选两位候选人，展示并排对比，写一条评审备注。
6. 人工加入入围名单，导出 CSV，结束演示。

接到企业正式 JD 后，需要替换岗位要求并重新确认参考标准。不要把演示结果称为模型准确率或真实招聘建议。
