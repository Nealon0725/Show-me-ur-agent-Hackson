# Clearhire：简历筛选界面

这是为 Resume Screening 黑客松题目完成的响应式前端。可以直接打开 `dist/index.html` 使用，也可以部署 `dist` 目录；推荐使用发布后的网址或 HTTP 预览，浏览器对本地 PDF 的预览支持可能不同。

## 已实现的界面与交互

- 简历筛选：三个岗位切换、姓名/职位/技能搜索、状态筛选、来源筛选、排序与分页。
- 候选人详情：四项岗位证据、原文引用、个人资料、评审备注。
- 简历预览：PDF 与作者文本版本切换，支持下载原始文件。
- 候选人对比：勾选同一岗位的 2–3 位候选人，并排查看工作证据。
- 入围名单：人工加入或移出候选人，导出 CSV。
- 文件导入：点击选择或拖放 PDF/TXT，检查类型、空文件、重复文件与 10 MB 大小限制，每次最多 20 份。
- 演示流程：明确标注使用预设结果的进度演示。
- 中英文界面切换，桌面、平板和手机布局，键盘焦点、弹窗关闭与减少动态效果支持。

样本数据包含之前准备的 60 位虚拟候选人，三个岗位各 20 人。PDF、姓名、经历和参考证据均为虚构。

## 必须准确表述的边界

**已经完成的是可操作的 UI 和前端交互，不是真实 AI 筛选服务。** 样本的证据状态来自预先编写的参考结果。运行演示不会调用模型，也不能当作已经完成 OCR、岗位分析或 AI 推理的证明。

新导入的文件不会发送到服务器，只在当前页面的内存中保存，刷新后消失；它们显示为「待分析」，不会套用样本答案。样本的入围选择、语言和已保存备注仅保存在当前浏览器，不在不同设备或团队成员之间同步。正式接入前需要由团队实现登录、权限、数据存储、AI/OCR 服务及共享评审记录。

中文模式翻译界面文字和岗位条目标题；英文简历原文、证据引文和完整岗位描述保留英文，方便现场展示及核对。

## 本地打开和修改

1. 完整解压源代码包，保留目录结构。
2. 打开 `dist/index.html`；如浏览器无法显示本地 PDF，可使用 HTTP 服务打开。
3. 修改界面逻辑：编辑 `dist/main.js`。
4. 修改视觉：编辑 `dist/styles.css` 和 `dist/accessibility.css`。
5. 修改样本：编辑 `dist/data.js`，保持候选人 ID 和岗位 ID 一致。
6. 修改 JavaScript 后运行 `node scripts/build.mjs`，重新生成 `dist/bundle.js`。CSS 和 HTML 修改无需此步骤。

项目无运行时第三方 JavaScript 依赖。界面使用 Apple 系统字体栈（SF Pro / 苹方优先），无需加载在线字体。图标使用内嵌 SVG；界面不加载真实候选人的头像。

可选 HTTP 预览示例：`python3 -m http.server 8765 --directory dist`，然后打开 `http://localhost:8765`。

## 目录

| 路径 | 用途 |
|---|---|
| `dist/index.html` | 页面入口，可以直接打开 |
| `dist/main.js` | 页面结构、状态、交互、浏览器保存及 WebMCP 注册 |
| `dist/data.js` | 三个岗位与 60 位虚拟候选人 |
| `dist/icons.js` | SVG 图标与文字转义工具 |
| `dist/styles.css` | 视觉样式、响应式布局、弹窗与动效 |
| `dist/accessibility.css` | 字体、对比度、窄屏和焦点修正 |
| `dist/apple-theme.css` | Apple 风格视觉系统、浅色材质、响应式细节与组件覆盖 |
| `dist/bundle.js` | 打包后的浏览器脚本，不直接编辑 |
| `dist/resumes/` | 60 份 PDF 附件 |
| `scripts/build.mjs` | 无依赖的脚本打包工具 |
| `设计与接入说明.md` | 视觉规则、交互与后端接入要点 |

## 三分钟演示顺序

1. 在「简历筛选」中选择软件开发岗位，说明 20 位候选人及四项条件。
2. 点击「运行演示」，明确这是 UI 演示，并展示流程状态。
3. 搜索一个技能，打开候选人，点击「查看原文」。
4. 切到「需澄清」，说明缺信息不等于能力不足。
5. 勾选两位候选人，展示并排对比，写一条评审备注。
6. 人工加入入围名单，导出 CSV，结束演示。

接到企业正式 JD 后，需要替换岗位要求并重新确认参考标准。不要把演示结果称为模型准确率或真实招聘建议。
